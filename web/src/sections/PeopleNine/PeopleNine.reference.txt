## What this screen is

A pale yellow shell with a brand chip, a pill nav and three counts — employees, open roles, projects. A large greeting sits above a four-stage funnel bar labelled interviews, hired, project time and payout, each stage carrying its own percentage. The left column is a week strip over a day schedule where meeting cards overlap their time slots, one in near-black and one in accent yellow. The centre is a salary table: five named rows with avatars, job titles, net salary and a paid, absent or pending state chip. The right column stacks a near-black attendance report built from a dotted matrix with a ratio read-out, above an employee-composition donut with a total in its centre and a two-part legend. A hiring-statistics panel closes the bottom with two lines — one black, one yellow — crossing over a twelve-month axis.

## Reproduce this exactly

- The funnel is one continuous bar in four labelled stages, not four separate bars.
- State chips keep three distinct values: paid, absent, pending. Collapsing them to two loses the point of the column.
- Meeting cards overlap in the schedule. Real days overlap and the layout should show it.
- The attendance matrix is dots on near-black — inverting it to dark dots on light breaks the column.
- The screen is authored on a fixed 1600x900 canvas in absolute pixels. `SectionFrame` scales that canvas to whatever width it is given. Do not convert the values to rem, percentages or viewport units — the layout depends on them being fixed.
- Every chart here is hand-drawn SVG with fixed sample data. Do not swap in Recharts, Chart.js, D3 or any other charting library: the shapes were drawn to fit their cards, not plotted from a series.
- Keep the markup structure and class names as written. The CSS is matched to them and selectors are not defensive.

```js
import { useCallback, useEffect, useRef, useState } from "react";

const reduced = () =>
  typeof window !== "undefined" &&
  window.matchMedia?.("(prefers-reduced-motion: reduce)").matches;

/**
 * Fires once when the element first scrolls into view. Every component
 * that animates on arrival uses this rather than animating on mount,
 * so nothing plays its entrance off-screen.
 */
export function useInView({ threshold = 0.25, once = true } = {}) {
  const ref = useRef(null);
  const [inView, setInView] = useState(false);

  useEffect(() => {
    const el = ref.current;
    if (!el) return;
    if (reduced()) {
      setInView(true);
      return;
    }

    const io = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          setInView(true);
          if (once) io.disconnect();
        } else if (!once) {
          setInView(false);
        }
      },
      { threshold }
    );

    io.observe(el);
    return () => io.disconnect();
  }, [threshold, once]);

  return [ref, inView];
}

/**
 * Eases a number up to its target on a rAF loop. Returns the live value
 * so the caller can format it however it likes (currency, %, compact).
 */
export function useCountUp(target, { duration = 1100, start = 0, run = true } = {}) {
  const [value, setValue] = useState(start);
  const frame = useRef(0);

  useEffect(() => {
    if (!run) return;
    if (reduced()) {
      setValue(target);
      return;
    }

    const t0 = performance.now();
    const tick = (now) => {
      const p = Math.min(1, (now - t0) / duration);
      // easeOutExpo — fast off the line, long settle
      const eased = p === 1 ? 1 : 1 - Math.pow(2, -10 * p);
      setValue(start + (target - start) * eased);
      if (p < 1) frame.current = requestAnimationFrame(tick);
    };

    frame.current = requestAnimationFrame(tick);
    return () => cancelAnimationFrame(frame.current);
  }, [target, duration, start, run]);

  return value;
}

/**
 * Pointer-tracked 3D tilt. Writes rotation and a glare position to CSS
 * custom properties so the surface can light up as it turns.
 */
export function useTilt({ max = 9, glare = true } = {}) {
  const ref = useRef(null);

  const onMove = useCallback(
    (e) => {
      const el = ref.current;
      if (!el || reduced()) return;
      const r = el.getBoundingClientRect();
      const px = (e.clientX - r.left) / r.width;
      const py = (e.clientY - r.top) / r.height;
      el.style.setProperty("--rx", `${(0.5 - py) * max * 2}deg`);
      el.style.setProperty("--ry", `${(px - 0.5) * max * 2}deg`);
      if (glare) {
        el.style.setProperty("--gx", `${px * 100}%`);
        el.style.setProperty("--gy", `${py * 100}%`);
      }
    },
    [max, glare]
  );

  const onLeave = useCallback(() => {
    const el = ref.current;
    if (!el) return;
    el.style.setProperty("--rx", "0deg");
    el.style.setProperty("--ry", "0deg");
  }, []);

  return { ref, onMouseMove: onMove, onMouseLeave: onLeave };
}

/** Compact currency / number formatting used across the data components. */
export const fmt = {
  money: (n, currency = "$") =>
    currency +
    n.toLocaleString("en-US", { minimumFractionDigits: 2, maximumFractionDigits: 2 }),
  compact: (n) =>
    n >= 1000
      ? (n / 1000).toLocaleString("en-US", { maximumFractionDigits: 1 }) + "K"
      : Math.round(n).toLocaleString("en-US"),
  int: (n) => Math.round(n).toLocaleString("en-US"),
  pct: (n, dp = 1) => n.toFixed(dp) + "%",
};
```

## File: `src/components/SectionFrame.jsx`

```jsx
import { useEffect, useRef, useState } from "react";
import "./SectionFrame.css";

/**
 * Every screen is authored on a fixed 1600x900 (16:9) canvas so the layout
 * stays pixel-identical everywhere. SectionFrame measures the width it has
 * been given and uniformly scales that canvas to match, so the screen always
 * fills its container edge to edge with no cropping and no scrollbars.
 *
 * It scales to *width* only, and takes its height from the 16:9 ratio in CSS.
 * That is what lets a screen drop into a page that already exists: it flows in
 * normal document order like any other block, rather than claiming the
 * viewport. Scaling to `min(width, height)` instead would letterbox the canvas
 * inside whatever height the host happened to give it.
 *
 * The ratio lives on `.frame` as an `aspect-ratio`, not in this component's
 * state. Height is then correct on the very first paint, before the effect
 * below has measured anything — driving it from `scale` instead renders one
 * frame at the full 900px and visibly collapses.
 *
 * `theme` is written to `data-theme` on the frame itself, which is what the
 * dark half of the token file keys off. Scoping it here rather than on
 * `<html>` means one screen can be dark on a light page.
 */
const DESIGN_W = 1600;
const DESIGN_H = 900;

export default function SectionFrame({ id, children, background = "#ffffff", theme }) {
  const hostRef = useRef(null);
  const [scale, setScale] = useState(1);

  useEffect(() => {
    const host = hostRef.current;
    if (!host) return;

    const fit = () => {
      const { width } = host.getBoundingClientRect();
      if (width) setScale(width / DESIGN_W);
    };

    fit();
    // Observing the host is safe here because its height is derived from its
    // own width by `aspect-ratio`, so nothing this callback does can feed back
    // into the measurement and loop.
    const ro = new ResizeObserver(fit);
    ro.observe(host);
    return () => ro.disconnect();
  }, []);

  return (
    <section
      id={id}
      className="frame"
      ref={hostRef}
      style={{ background }}
      data-theme={theme}
    >
      <div
        className="frame__canvas"
        style={{
          width: DESIGN_W,
          height: DESIGN_H,
          transform: `scale(${scale})`,
        }}
      >
        {children}
      </div>
    </section>
  );
}
```

```jsx
function Nav() {
  const [active, setActive] = useState(0);
  const [box, setBox] = useState(null);
  const wrap = useRef(null), refs = useRef([]);
  useLayoutEffect(() => {
    const measure = () => {
      const el = refs.current[active], host = wrap.current;
      if (!el || !host) return;
      const a = el.getBoundingClientRect(), b = host.getBoundingClientRect();
      // SectionFrame scales the whole canvas, so rects come back in visual px
      // while the marker is positioned in layout px — divide the scale back out
      const scale = b.width / (host.offsetWidth || b.width || 1);
      const n = { left: (a.left - b.left) / scale, width: a.width / scale };
      // the equality guard is load-bearing: without it every measure sets a new
      // object and the observer below re-renders forever
      setBox((p) => (p && Math.abs(p.left - n.left) < .5 && Math.abs(p.width - n.width) < .5 ? p : n));
    };
    measure();
    // webfonts land after first paint and change the tab widths, and the tab
    // that is active at mount never re-runs this effect on its own
    document.fonts?.ready.then(measure);
    const ro = new ResizeObserver(measure);
    if (wrap.current) ro.observe(wrap.current);
    return () => ro.disconnect();
  }, [active]);
  return (
    <div className="p9__nav" ref={wrap}>
      {box && <span className="p9__navMark" style={{ transform: `translateX(${box.left}px)`, width: box.width }} />}
      {TABS.map((t, i) => (
        <button key={t} ref={(el) => (refs.current[i] = el)} data-active={i === active} onClick={() => setActive(i)}>{t}</button>

  );
```

## Design notes (context, not instructions to change anything)

- The schedule positions cards by start time and duration against a fixed pixel-per-minute constant, so two overlapping meetings genuinely overlap rather than being nudged by hand.
- The salary table is a CSS grid with named columns rather than a `<table>`, because the state chip and the avatar cell need alignment rules a table cell fights.
- Yellow is a hard accent to read text on, so every label over an accent surface is near-black rather than white — the one place in the set where the accent's contrast colour is dark.
- The two hiring lines are deliberately allowed to cross. A chart where the series never meet is a chart that did not need two series.
- The dotted attendance matrix reuses the same index-maths idiom as the widget board's profit grid and the finance desk's activity strip.
- `SectionFrame` scales to width only and takes its height from a 16:9 `aspect-ratio` in CSS. That is what lets the screen flow inline instead of claiming the viewport. Because the canvas is fixed at 1600x900, everything shrinks together — on a narrow phone the whole screen scales down uniformly, so treat this as a wide-layout screen and give narrow viewports a different treatment if you need one.
- `tokens.css` and `base.css` are scoped with `:where(.frame)`, which contributes no specificity. That matters: written plainly, `.frame button` would outrank the screen's own single-class rules and silently restyle its controls. The scope keeps the reset landing exactly where a global `*` and `button` rule would.
- The token names are deliberately generic — `--bg`, `--ink`, `--line`, `--surface`. They are declared on the frame rather than `:root` so a project that already uses those names is not quietly redefined.
- All data is hard-coded sample data. Nothing is fetched, no control recalculates anything, and every figure is invented — wire your own data in where the constants sit at the top of the component.
